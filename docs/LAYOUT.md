# 瀑布流收尾排布

整页是一条瀑布流。流式期间块一块块落下，高度都是估的；生成结束、图片和图表都出完之后，
必须再做一次排布 —— 否则页面上会留下大段空白，而且间距对不上。

- 实现：`packages/catalog/src/layout/masonry.js`（纯函数）
- 实验台：`/layout-lab.html`（同数据对比三种排法）
- 测试：`bun tests/layout.mjs`

## 实测

`demos.html` 三列，画布 950px，列宽 309，间距 12：

| 位置 | 现象 |
|---|---|
| 分节标题（全宽块）前 | 第 2、3 列停在 518，标题落在 646 → **116px 空条** |
| 页尾 | 第 1 列到 898，另两列停在 518 → **380px 空白** |

收尾跑完（`demos.html` 的 Q3 复盘，13 块 3 列）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 屏障空条 | 118 / 76 / 76（三处） | **118（一处）** |
| 块重叠 | 0 | 0 |
| 列内间距异常 | 0 | 0 |

## 根因

| # | 代码 | 问题 |
|---|---|---|
| 1 | `Grid.js` 贪心 | 只看已落下的块，按「当前最矮的列」放。高度是估的，估错了也不回头 |
| 2 | `Grid.js` span 分支 | 全宽块取 `max(各列下沿)`，然后把每列都推到它下面。短列上方那段从此再也填不上 —— **大片空白全部来自这里** |
| 3 | 没有收尾 | 骨架高度 → 真实高度、图表异步出图、图片加载，每次都触发重排，但重排仍是贪心；没有一次「全部高度已知」的全局求解 |

## 不变量

排布结果必须满足：

1. 同列相邻两块，间距 = `gap`（±0.5px）
2. 任意两块不重叠
3. 全宽块之后的块，`y ≥` 该块下沿
4. 页高 = 最底列的 `y + h`
5. 同样输入两次，逐块一致
6. 补白后，块高只增不减，且增量 ≤ 上限

## 方案

### 1. 收尾一次（时机）

只在「高度全部确定」之后排，流式期间不追最优。

```
流式结束（runTurn 末尾）
  → document 发 openui:turn-end
  → 无 Placeholder（还有骨架就每 220ms 再看一次，最多 6 次）
  → 高度静默 220ms
  → 完整束宽排一次 → 补白 → 过渡 320ms
```

- 排完比对结果，逐块相同就不动（幂等）
- 窗口 resize、块内高度变化（图表出图）走同一入口，沿用「已收尾」模式
- 新一轮开始（`openui:turn-start`）关掉过渡，回到便宜排法

### 2. 求解（束搜索替代贪心）

状态 = 每列当前下沿 + 上一块的 y 与列号；动作 = 这一块从哪列开始。

代价四项：

| 项 | 权重 | 作用 |
|---|---|---|
| 页高（最终最高列） | 1 | 整页最紧 → 尾部最平 |
| 列间落差（最高列 − 每列，求和） | 1 | **压「块全挤在前两列」**，页高相同但第三列空一大截 |
| 屏障残差（全宽块落下时短列上方的空条） | 1.2 | 直接压大空条 |
| 抬升 + 换列距离 | 0.05 / 1 | 保阅读顺序，不为了省 20px 把块甩到另一头 |

束宽 32，13 块 3 列实测 < 5ms。同列内相对顺序天然保持（按顺序逐块放）；跨列可以乱 —— 那是瀑布流本意。

### 3. 屏障（全宽块）

全宽块是硬边界，后块不能越过去。它前面的残差只有三条出路：

| 出路 | 做法 | 代价 |
|---|---|---|
| 补白 | 该列最后一块向下补到屏障。上限 = 块高 30%，夹在 [24, 96] | 残差大时卡片下方留白 |
| 整块下延 | 跨列块要补，得它覆盖的每一列残差相同，否则会把另一列顶出新缝 | — |
| 降级 | 残差超阈值时把整行标题改成普通块再排一遍（`barrier: 'auto'`） | 标题变成 1/3 宽 |

默认 `keep`：只补白，不降级。降级是产品决策，不是布局决策。

补白只补「扣掉间距之后」多出来的那段 —— 列底到屏障本来就该留一个 gap，把那 12px 也补掉会毁掉间距恒定。

### 4. 流式期间

| 阶段 | 排法 | 过渡 |
|---|---|---|
| 流式中 | 同一求解器，`beam: 8` | **关**（块直接出现在最终位置，不滑） |
| 收尾 | `beam: 32` + 补白 | **开**（320ms） |

流式期间开过渡 = 每来一块整页抖一次。只在收尾那一次让块「相互移动」，才看得出来是收口。

## 接口

```js
packMasonry(items, { cols, gap, width, absorb, barrier, beam })
// items: [{ id, span, height }]  →  { positions, pageBottom, gaps, barrierGap, tailGap, ... }
```

- `positions[].y` 是像素，直接写 `transform`
- `gaps` 是空条清单（`col / y / h / kind`），`kind` 分 `barrier`（该压）与 `tail`（正常）
- 不碰 DOM，渲染侧只负责写 transform

事件约定（Grid 只听这两个，不再和会话耦合）：

| 事件 | 谁发 | Grid 做什么 |
|---|---|---|
| `openui:turn-start` | `session.runTurn` 开始画界面 | 切流式模式：beam 8、关过渡 |
| `openui:turn-end` | `session.runTurn` 收尾 | 等 220ms 静默 → beam 32 + 补白 + 开过渡 |

补白靠 `min-height` 实现：每轮排布开始先把上一轮的 `min-height` 清掉再量高度，所以不会累积。

## 验收

| 断言 | 位置 |
|---|---|
| 间距恒等、不重叠、屏障不越界、确定性、补白上限、降级 | `tests/layout.mjs`（18 条） |
| 新旧对比：页高不变高，多数组变矮 | 同上 §4 |
| 页面上量矩形：`gaps` 为空或只剩 `tail` | 实验台右下角读数 |

## 不做的

- 不换 CSS Grid 的 `span` 拼法（取整误差与空洞，已在 `Grid.js` 注释里否掉）
- 不做「跨屏障回填」：块跑到分节标题上面，视觉上是错的
- 不做等高拉伸（`stretch` 到同高）：内容比例会乱，只按块高 30% 补白（夹在 24–96px）

## 分段拉齐 + 换宽度（顺序不变）

目标：每段（两道整行标题之间）各列底边齐平，成一个矩形。

| 层 | 做法 | 参数 |
|---|---|---|
| 换宽度 | 收尾时量每块在「声明下限..cols-1」列宽下的高度，beam 在这些跨列数里挑 | `alts`、`spanWeight` 30 |
| 拉齐 | 每列末块向下拉到本段最低列底边，位置不动 | `equalize { ratio 0.85, max 400, min 48 }` |
| 补白 | 整行标题前的小残差 | `absorb` 96 |

- 块顺序不变；拉伸上限按拉伸前高度累计
- 跨列块须是其覆盖各列的唯一末块才拉，差额取最小
- `.grid-item > .card:only-child { flex: 1 }`：外层加 min-height 后卡片跟着撑满
- 实测 Q3：段一 444/444，段二 450/450，空条 0，重叠 0；`bun tests/layout.mjs` 29 条

## 流式只落位，收尾排一次

| 阶段 | 求解 | 动画 |
|---|---|---|
| 流式 | `packSticky`：已落位块列号不动，新块进最矮列 | 无 |
| 收尾（turn-end + 220ms 静默 + 无骨架） | `packMasonry`：beam + 换宽度 + 拉齐，仅一次 | 位置、宽度、min-height 同时过渡 380ms |

- 动画起点：量尺寸前先记下当前宽高；量尺寸时挂 `.masonry-measuring` 关过渡，写回起点后再开过渡
- 动画期间（420ms）`ResizeObserver` 回报不触发重排
- 骨架被成品替换时新块继承旧块列号
- 实测 Q3 流式：换列 0；收尾高度 368→444、332→450 逐帧过渡
- 流式中仍有上移：骨架换成品后变矮，下方块顺势上移，非重排

## 声明宽度是硬下限（24 栅格）

### 问题

收尾「换宽度」原来给每个非整行块量 `1..cols-1` 的所有列宽，求解器为了压页高可以
把 `GridItem(..., 2)` 的表格换成 1 列。截图里的「销售明细」就是这样被挤成窄条的：
模型已经声明了跨 2 列，但自动排版把它当成了「建议值」。

### 契约

`GridItem(children, span?, width?, height?)`

| 参数 | 含义 | 默认 |
|---|---|---|
| `span` | 当前画布下跨几列（旧写法，继续有效） | 1 |
| `width` | **24 栅格**里的最小宽度：8=1/3、12=1/2、16=2/3、24=整行 | 不额外约束 |
| `height` | 最小高度（px） | 不额外约束 |

- 实际最小跨列数 = `max(span, ceil(width / 24 × cols))`，向上取整，保证不会比声明窄
- 收尾只量 `minSpan..cols-1` 的高度；低于 `minSpan` 的 `alts` 在归一化时直接丢弃
- 流式 `packSticky` 也用同一个 `minSpan`，所以表格从出现的第一帧就是宽的
- `height` 在量高度前挂成 `min-height`；收尾只会补高，不会压扁
- 列数变化时按比例重算：3 列下 `width:16` → 2 列；4 列下 → 3 列；1 列下 → 1 列

| 文件 | 改了什么 |

### 不做的

- 不把 `width` 当百分比硬切：列宽必须落在整数列上，向上取整是唯一不会违反「最小宽度」的取法
- 不让 `height` 参与换宽度求解：高度是内容属性，宽度才是排布属性
